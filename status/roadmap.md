# Proposed next steps

This is a dependency-ordered proposal, not an active campaign, schedule or authorization to spend. The user decides the next project objective after opening this repository in Codex.

| Order | Work | Completion evidence | Boundary |
|---:|---|---|---|
| 1 | Choose one narrow ICP, geography and workflow | Completed ICP worksheet, exclusions and sample cap | Cleaning is a candidate, not an assumed decision |
| 2 | Resolve permitted source and identity process | Source rights, field meanings, source date and identity rules | Explain any dataset/export download before doing it |
| 3 | Review a small private sample | Identity/access/fit outcomes, reproduced tasks, no-issue/unknown counts | No bulk expansion or outreach from mere registrations |
| 4 | Select a reusable demonstration | Buyer task, fixture data, acceptance tests, setup/maintenance estimate | No invented live integration or customer relationship |
| 5 | Validate an offer through authorized conversations | Recognized need, capacity, data access, buyer and acceptable scope | Email hold remains; no autonomous contact |
| 6 | Deliver one paid scoped pilot if agreed | SOW, approved access, tested workflow, actual time/cost and result | Deployment and production access require their own scope |
| 7 | Reprice and standardize from evidence | Support logs, exception rate, cancellations and margin | Do not extrapolate small samples into proven long-run churn |
| 8 | Add adapters or scale only when useful | Data gap, terms/account evidence, bounded budget and regression tests | No automatic paid provider activation or thousand-company run |

The source engine includes a proposed 100-to-1,000-input plan. That is a later scaling design, not a completed experiment. Begin with the smallest sample that tests source quality and qualification mechanics, then expand only after useful evidence.

Technical follow-ups, if selected: isolated spend-dashboard browser QA; a workbench adapter that emits pending suggestions; complete shared suppression; secure private multiuser storage; additional trusted audit profiles; and provider cost reservation/reconciliation. These are independent backlog items, not prerequisites for writing a useful strategy or manually qualifying a small sample.

For content research, maintain exact links, dates, review coverage and evidence classes as new examples are added. A refresh cadence can be chosen later; this repository does not create background research or monitoring.
