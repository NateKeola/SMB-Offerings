The user will create the project from this repository. The following prompt supplies context; it does not authorize a deployment, campaign, purchase or merge.

## Paste this prompt

> Read AGENTS.md, README.md, strategy/vision-and-preferences.md, strategy/decision-register.md, status/current-state.md and status/source-projects.md. This repository is the public handoff for my SMB service and outreach work. Preserve my “proven, better, new” preference: start with existing demand and a concrete improvement, using new AI capabilities only when useful. Consider established businesses across industries; do not assume cleaning or Shopify is my chosen market.
>
> Continue from the existing research and exact source commits rather than restarting or claiming the five draft PRs are merged. Clearly distinguish user decisions, observed evidence, implementation status, hypotheses and unknowns. Current code lives in the linked Dogfood PRs; this repository is documentation and templates.
>
> Help me choose the next bounded step from status/roadmap.md. First summarize what exists and the most material gaps. Inspect the repository and available source context before asking for missing information. Prefer permitted official business sources, verify identity before website diagnosis, and test real customer tasks. An absent website field, old design or missing chatbot does not establish an opportunity.
>
> Keep real leads, contacts, private reports and credentials out of the public repo. Do not send emails; that hold remains active. Do not execute calls, messages, visits, paid API requests, deployments or account integrations without my instruction for that action. Explain the exact item and reason before any new download. No need to create another Codex project or merge the source PRs automatically. Make the next result concrete and reviewable, and keep the decision/status documents current as we work.
