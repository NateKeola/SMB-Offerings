This summarizes the toolkit reviewed **2026-11-02** at [commit 171d93bd](https://github.com/NateKeola/Dogfood/tree/171d93bd4635f68ffb9df26b83ef5acb0f2d297a/projects/seo-review). It is a planning reference, not a completed client audit or a new check of every external source. Recheck changeable platform guidance before implementation.

The full [62-entry primary-source register is included here](source-register.md), including dates, source limitations and decisions affected by newer evidence.

## Offer useful outcomes

Sell a scoped search-readiness review, industry/intent brief, website-build specification, AI-search/agent-usability review, measurement plan or post-change verification. Each should explain what was observed, the source, business relevance, priority, lift, validation and limits. Keep local-service and wholesale buying tasks distinct. Qualitative research is not keyword-volume data.

Choose a few useful actions from a bounded assessment. Do not invent traffic, conversion rates, search volume, customer addresses, expertise, reviews or backlinks. A business should receive a dependency-ordered backlog and a measurement plan tied to qualified inquiries, not a guaranteed ranking or inclusion claim.

## Files and controls are different

| Mechanism | What the reviewed toolkit distinguishes |
|---|---|
| `robots.txt` | Crawler-specific preferences; not authentication or a universal deletion mechanism |
| `sitemap.xml` | Discovery/canonical hints for supported engines; no guaranteed crawl/index outcome |
| `llms.txt` | Optional context/link proposal with specific consumer/tool support; not a universal search requirement or promised ranking lever |
| `AGENTS.md` | Repository instructions for coding agents; not a business site's SEO feature |
| `agents.txt` | Ambiguous proposals, not one established search standard; name the version and actual consumer before experimenting |

The toolkit separates search discovery, user-directed fetch and model training. It records distinct OpenAI and Anthropic bot roles, Google Search AI controls/reporting and their scope, and the difference between a documented product feature and a proposal. Do not flatten these into one allow-all crawler template or weaken protected staging for a test. The detailed [AI module](https://github.com/NateKeola/Dogfood/blob/171d93bd4635f68ffb9df26b83ef5acb0f2d297a/projects/seo-review/AI_SEARCH.md) and [62-source bibliography](https://github.com/NateKeola/Dogfood/blob/171d93bd4635f68ffb9df26b83ef5acb0f2d297a/projects/seo-review/SOURCES.md) retain the dated technical evidence, including later updates that superseded older guidance.

Use useful original content, truthful entity/business facts, ordinary technical foundations, semantic controls, accessible forms and structured data that matches visible facts. Missing optional files alone are not a serious defect. Browser-agent usability is not proof of citation improvement.

## Seven website launch gates

| Gate | Evidence required |
|---|---|
| G1 Scope and truth | Owner-approved facts/claims, real service area, privacy and publishable content |
| G2 Environment and discovery | Correct host/routing, intended robots/index/canonical/sitemap behavior, protected staging and reachable rendered pages |
| G3 Content and navigation | Useful pages, clear questions/actions, titles/headings/links and no copied or doorway content |
| G4 Structured data | Truthful visible fields, appropriate types and validation; choosing no rich-result markup can be valid |
| G5 Usable conversion path | Agreed desktop/mobile/keyboard success and error paths; disabled demo actions clearly labeled |
| G6 Performance | Repeated lab tests against agreed budgets; field data separately reported, unknown if unavailable |
| G7 Release and measurement | Known build, release owner, authorization, rollback/regression plan, baseline and evidence gaps |

Use the full [build checklist](https://github.com/NateKeola/Dogfood/blob/171d93bd4635f68ffb9df26b83ef5acb0f2d297a/projects/seo-review/BUILD_CHECKLIST.md). Unknown is not pass. Non-website research/GTM briefs need not pretend to satisfy website gates.

## Measurement and tools

Separate traditional search impressions/clicks, AI mentions/citations, referrals, qualified inquiries and fulfilled business outcomes. A lab performance score is not revenue. Record the coverage and definitions of each reporting surface; do not assume UI reports have equivalent APIs or that a connected tool grants property access.

For a manual AI-search panel, retain the exact query, surface/model, time, locale, session conditions, citation URL, factual accuracy and limitations. Keep non-mentions in the denominator and repeat observations to reveal variability. Report observed X of Y sampled answers, not a universal share/rank. Before/after changes alone are not causal evidence.

The toolkit's [tools and lift module](https://github.com/NateKeola/Dogfood/blob/171d93bd4635f68ffb9df26b83ef5acb0f2d297a/projects/seo-review/TOOLS_AND_LIFT.md) covers Search Console, GA4, PageSpeed, CrUX, Bing, crawlers and optional paid data. Prices, quotas, permissions and API eligibility need current confirmation. No accounts, tracking, search submissions, crawler settings or paid tools were changed by this handoff.
