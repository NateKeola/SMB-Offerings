# Prototype offer and SOW — blank template

Draft only. Complete with the business and authorized reviewer before promising implementation. Keep customer versions private.

| Section | What to record |
|---|---|
| Problem and evidence | Specific task, observed behavior, buyer confirmation and uncertainty |
| What exists today | Artifact, checked behavior, date and explicit simulation limits |
| Proposed improvement | One useful workflow and why it may matter |
| Customer value measure | Baseline, task success, staff time or qualified outcomes; no invented uplift |
| Included scope | Pages/products/variants/suppliers/locations/endpoints and revision counts |
| Exclusions | ERP/auth/payments/booking/CRM/migration unless deliberately included |
| Client dependencies | Approved facts/assets, rights, access owner, test destination and response responsibility |
| Data handling | Private destination, permissions, retention, logging and sensitive-data exclusion |
| Delivery phases | Discovery → fixture demo → authorized integration → acceptance → authorized launch |
| Acceptance | Success/error/no-result paths, mobile/keyboard, grounded facts, freshness, appropriate SEO gates |
| Effort and schedule | Hands-on range, waiting dependencies and re-estimate triggers |
| Setup price | Assumption or agreed quote; diagnostic credit treatment; taxes/fees |
| Recurring service | Named obligation, minutes, included tools/usage, response target and overage/change process |
| Ownership and exit | Domain/content/code responsibilities, export, cancellation and handoff |
| Release and recovery | Authorization, version, backup, rollback and responsible owner |
| Post-change measurement | Period, denominator, confounders and low-volume limits |
| Open decisions | TBD; unknown does not equal pass |

Do not present a prototype price as a production integration quote. Do not promise rankings, AI inclusion, revenue, autonomous accuracy or unlimited support.
